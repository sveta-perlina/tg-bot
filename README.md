# 🤖 KS Bot — Бот Клиентского Сервиса

Бот в Пачке для автоматической обработки выгрузок в дни запуска учебных потоков. Принимает файлы из АМО и Суперсета, совмещает их и отдаёт готовую таблицу для переноса студентов в мониторы кураторов.

---

## Что делает бот

1. Принимает `.xlsx`-файлы в чат Пачки.
2. Автоматически определяет тип каждой таблицы (сырая АМО, подготовленная АМО, выгрузка из Суперсета/ЛМС).
3. Обрабатывает и совмещает данные.
4. Возвращает итоговый файл с тремя листами:
   - **«Заносим в мониторы»** — студенты, найденные и в АМО, и в Суперсете; их сразу вносим в мониторы кураторов.
   - **«Есть в АМО, нет в суперсете»** — спорные студенты; передаются в ТАС.
   - **«Есть в суперсете, не было в АМО»** — студенты из Суперсета без записи в АМО; тоже идут в ТАС.
5. Если среди студентов есть оплаты через Lerna KZ / Lerna RB / Jusan mart / счёт — отдельно присылает файл `lerna.xlsx` с инструкцией по промокоду.

> ⚠️ **Персональные данные.** В обрабатываемых таблицах содержатся персональные данные студентов (ФИО, email, телефон). Не передавайте файлы по незащищённым каналам и не оставляйте их в публичном доступе.

---

## Режимы работы

Бот сам определяет сценарий по набору присланных файлов.

| Режим | Что прислать | Что происходит |
|-------|-------------|----------------|
| 🔵 **Режим 1** — предобработка АМО | Только сырая выгрузка из АМО | Бот готовит `to_monitors.xlsx`. Нужно вручную добавить второй лист с выгрузкой из Суперсета и прислать снова. |
| 🟢 **Режим 2** — сопоставление | `to_monitors.xlsx` (подготовленная АМО) + выгрузка из Суперсета | Полное совмещение, готова итоговая таблица. |
| 🟣 **Режим 3** — полный автомат | Сырая АМО + выгрузка из Суперсета одним сообщением | Бот сам готовит АМО и сразу совмещает. Самый быстрый путь. |

## Структура ожидаемых таблиц

### Сырая выгрузка из АМО
Обязательные столбцы: `Продукт`, `Название сделки`, `Основной контакт`, `Номер потока`, `Тип оплаты`, `Бюджет`, `Рабочий email (контакт)`, `Другой email (контакт)`, `Рабочий телефон (контакт)`, `Другой телефон (контакт)`, `Теги сделки`, `Должность (контакт)`, `patronymic (контакт)`.

### Подготовленная АМО (to_monitors)
Столбцы после предобработки: `Продукт`, `Имя`, `Фамилия`, `Почта`, `Тариф`, `Тип оплаты`, `Доп статус`, `Come in поток`, `Переводы`, `Now поток`, `Техполе_1`, `Техполе_2`.

### Выгрузка из Суперсета / ЛМС
Обязательные столбцы: `Поток`, `Студент`, `Фамилия`, `Имя`, `Почта`, `Посл. Активность, дни`, `Балл студента`, `Возможный балл`, `Прогресс`.

## Запуск

### Переменные окружения

Скопируйте `.env.example` в `.env` и заполните:

```env
YOUR_TOKEN=           # API-токен бота из настроек Пачки → вкладка «API»
CHAT_ID=              # ID чата, в который бот отправляет ответы (например, 39634140)
BOT_ID=               # user_id бота из настроек Пачки → вкладка «API»
WEBHOOK_SIGNING_SECRET= # Секрет подписи исходящего вебхука Пачки

BOT_WORKDIR=/tmp/ks_bot                # Рабочая директория (можно оставить по умолчанию)
WEBHOOK_REPLAY_WINDOW_SECONDS=60       # Окно защиты от replay-атак, секунды
```

> `WEBHOOK_SIGNING_SECRET` — чувствительный секрет. Никогда не коммитьте его в репозиторий и не передавайте в открытых каналах.

### Docker (рекомендуется)

```bash
docker build -t ks-bot .
docker run --env-file .env -p 8080:8080 ks-bot
```

### Локальный запуск

```bash
pip install -r requirements.txt

# Webhook-режим (основной):
uvicorn webhook_app:app --host 0.0.0.0 --port 8080

# Polling-режим (альтернативный, для отладки):
python ks_bot.py
```

## Архитектура

```
ks_bot.py          — вся бизнес-логика: парсинг, мэтчинг, формирование Excel
webhook_app.py     — FastAPI-приложение; принимает вебхуки от Пачки
requirements.txt   — зависимости Python
Dockerfile         — образ на python:3.12-slim, запуск через uvicorn
.env.example       — шаблон переменных окружения
```

**Стек:** Python 3.12, pandas, openpyxl, FastAPI, uvicorn, pachca-sdk, httpx.

**Вебхук Пачки** настраивается на endpoint `POST /pachca/webhook`. Есть защита подписью HMAC-SHA256 и защита от повторной доставки (replay window).

**Polling-режим** (`python ks_bot.py`) — альтернативный режим без вебхука, опрашивает очередь событий каждые 2 секунды. Удобен для локальной отладки.
